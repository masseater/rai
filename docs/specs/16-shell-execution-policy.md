# 16 — 外部プロセス起動ポリシー

## 目的

`rai` は個人ユーザー向けの CLI であり、ユーザーが日常の対話シェル
(fish / zsh / bash 等) で組み立てているコマンドを **そのまま** 受け取れることを
体験の核とする。fish の `function` や zsh の `alias` のような「シェル機能としてしか
解決できない名前」(例: `ccs_print`) も、ユーザーから見れば "コマンド" であり、
これを `rai` 経由で呼べないのは体験の欠陥である。本 spec は `rai` が外部プロセスを
起動する際の挙動を、ユーザーから見える契約として規定する。

## 機能要件

- `rai` から外部コマンドを起動する場合、起動はユーザーのデフォルトシェル
  (環境変数 `SHELL`、未設定時は `/bin/sh`) を介して行われる。
- 起動コマンド文字列は、ユーザーがそのシェルの対話プロンプトに直接入力した場合と
  同等に解釈される。すなわち以下が成立する:
  - シェル関数・alias・組込みコマンドが解決される。
  - パイプ・リダイレクト・コマンド置換などのシェル構文が利用できる。
  - `~` 展開・環境変数展開・globbing がそのシェルの仕様どおりに行われる。
- ユーザー指定の文字列 (例: `--engine-cmd`) は、シェル文字列としてそのまま
  シェルに渡される。`rai` 内部でトークン分割した結果を `execvp` で直接起動しては
  ならない。
- `rai` がプロンプト等を引数として外部コマンドに差し込む場合、その引数は
  起動先シェルの構文で安全にクォートされなければならない。POSIX 系シェル
  (sh / bash / zsh) と fish ではクォーティング規則が異なるため、`rai` は
  どちらの規則でも壊れない引数を生成する。
- 起動先シェルの判定は `SHELL` の basename を使う。`fish` なら fish 規則、
  それ以外は POSIX 規則を採用する。
- 例外: `rai` がそのシェル自身を起動する場合 (本ポリシーを実現するための
  `$SHELL -c '...'` 起動) は当然この限りでない。

## 受け入れ条件

- [ ] ユーザーが fish の function として定義した名前 (例: `ccs_print`) を、
      `rai` の任意の `--engine-cmd` 系オプションにそのまま渡して動作する。
- [ ] パイプを含むコマンド文字列 (例: `foo | bar`) を `--engine-cmd` に
      渡して、ユーザーが対話シェルで実行した場合と同じ結果になる。
- [ ] `rai` が差し込むプロンプト等の引数に空白・引用符・バックスラッシュが
      含まれていても、起動先シェルが 1 引数として受け取る。
- [ ] `SHELL=/usr/local/bin/fish` の環境で起動した `rai` から呼ばれた
      コマンドが fish 構文で評価される。`SHELL=/bin/zsh` 等では POSIX 構文で
      評価される。
- [ ] `rai` の出すエラーメッセージで、コマンドが見つからない原因がシェルに
      由来する (関数未定義など) のか、`rai` 側の起動失敗かをユーザーが区別できる。

## 期待する成果物

- `rai-core` に外部プロセス起動の共通ユーティリティを置き、各サブコマンド
  クレートはそこを経由してのみ外部コマンドを起動する。
- 既存サブコマンドのうち、外部コマンドを `execvp` 直叩きしているものを
  本ポリシーに沿って統一する。
- `AGENTS.md` の "External Process Execution" セクションは本 spec を要約した
  運用上の指針として保持する (SSOT は本 spec)。

## 非対象

- ユーザーのシェルそのものの設定・インストール・補完。
- リモートホスト上での実行 (ssh 越しのコマンド起動など)。
- Windows ネイティブシェル (cmd.exe / PowerShell) のサポート。本リポジトリは
  POSIX 系 (macOS / Linux) のみを対象とする。
- 外部コマンドの戻り値・stdout/stderr の意味付け。これらは各サブコマンド
  個別の spec が規定する。

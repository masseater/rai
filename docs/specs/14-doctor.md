# 14 — `rai doctor`

## 目的

`rai` の各サブコマンドが依存している外部 CLI ツールが、ローカル環境で実行可能な状態にあるかをワンコマンドで確認する。新しい環境で `rai` を入れたユーザが、何が足りないかすぐ分かる状態を作る。

## 想定ユーザー

- 新しいマシンで `rai` をセットアップした人。
- `rai issue develop` などが動かなくなり、必要ツールが入っているかを確認したい人。

## 機能要件 (何をするか)

- `rai doctor` を実行すると、依存ツールごとに「見つかったか」「（取得できれば）バージョン文字列」を 1 行ずつ表示する。
- 確認対象は最低限以下:
  - `git` / `gh` / `gwq` / `tmux` / `fzf` / `claude` / `ccs` / `tee`
- ユーザの `$SHELL` を表示する（`rai issue develop` の wrapping が POSIX/fish のどちらに分岐するかが分かるように）。
- 1 つでも見つからないツールがあれば終了コード `1`、すべて揃っていれば `0`。
- 出力は人間向け。stdout に出す。色付けは TTY のときだけ ON にする（`NO_COLOR` を尊重）。

## CLI 仕様

```
rai doctor
```

- 引数なし。
- 終了コード:
  - すべての依存ツールが見つかった: `0`
  - 1 つ以上欠けていた: `1`

## 受け入れ条件

- [ ] `rai doctor` を実行すると、依存ツール一覧と各ツールの存在ステータスが表示される。
- [ ] 既知のツールが PATH 上で見つかれば `ok` 表示と version の先頭行が出る。
- [ ] 既知のツールが PATH 上で見つからなければ `missing` 表示が出て、コマンドは終了コード `1` で終わる。
- [ ] 出力には `$SHELL` の値が含まれる。
- [ ] サブコマンドが追加されても、依存ツールリストはコード内の単一の場所で増減できる（ハードコード重複を避ける）。

## 期待する成果物

- `crates/cmd/rai-cmd-doctor` crate (`rai doctor` 本体)。
- `rai doctor` を `rai` 本体に配線。
- ユニットテスト: 依存ツール表示行の生成ロジックに対して、`ok` / `missing` の両ケース。

## 非対象

- 自動インストール (`brew install gh` 等の実行)。doctor は診断のみで副作用を持たない。
- バージョン要件の比較。「入っていれば OK」までを対象とする。
